# 备用域名 backupHosts

仅用于路径、作品 ID、章节 ID 和接口语义一致的同站镜像。模板相同但数据不同的独立网站仍应使用不同规则。

```json
{
  "host": "https://www.example.com",
  "backupHosts": ["https://mirror.example.net", "https://mirror.example.org"]
}
```

`backupHosts` 可省略，最多 8 个。填写完整 HTTP(S) 来源，不含路径、参数、片段、账号密码；会去重并移除重复主域名。HTTPS 主站不允许 HTTP 备用域名。编辑页可每行填写一个域名，导出时为数组。

## 自动选址

- 首次发起站内读请求时，主站和备用域名并发做无凭据轻量 GET 探测。仅使用响应前段，不提交搜索、登录或其他业务表单，不保存探测 Cookie。最先返回正常响应者获选，错误状态、已识别的验证占位页不作为正常响应。
- 同一规则的同时请求共享一次选址。当前会话使用 10 分钟滑动缓存，持续请求延长有效期；长时间闲置、缓存失效或主动重新检测才重新测速，不为每张图片反复测速。重启应用后重新选择，手动固定设置保留。
- 只有连接/超时/TLS 故障及 408、502、503、504 可对无请求体 GET/HEAD 触发一次重选和一次重试。401、403、404、429、登录/验证错误、解析为空不会触发业务重试。
- 公开的 JSON/表单 POST 查询也可向选中域名提交一次，但不会因失败自动重放。包含账号、密码、Token 等字段、不透明请求体及其他有副作用方法默认保留原地址，跨来源需明确授权；手动固定也不绕过认证限制。原生登录提交始终使用 `auth` 明确声明的地址。
- 探测首页不是对业务页面的验证：若首页探测全部失败（例如入口需要登录或验证码），会保留原地址尝试业务请求；用户也可手动固定已知可用域名。探测只衡量当前响应，不保证后续吞吐率或内容一致性。

## 地址与凭据

请求时仅改写主站/备用列表内的来源，保留实际路径、编码、参数及片段；相对链接继续由现有 baseUrl 解析，传输层再映射至选中来源。第三方 CDN、外部 API 不改写。站内图片、流式资源沿用同一选址；原始页面或资源内部直接访问的第三方 URL 不扩展此列表。

切换在认证注入之前发生。Cookie、Authorization、Host 和已声明的认证头不会原样跨来源转发；认证头按实际目标的 `auth.inject.origins` 和 pathPrefix 重新评估，Cookie 仍按各自来源保存。备用域名不自动加入认证信任范围。已有登录态或敏感参数时，自动选择会排除未获授权的其他来源，保留原来源；敏感请求体默认保留原地址。手动选择未获授权的其他来源会提示切回主站或完善认证配置；可能需要该来源独立的登录入口。手动固定也不会绕过这个限制。签名如果依赖域名，作者应验证实际目标域名的签名语义，不能只依靠替换 Host。

## 手动选择

规则管理的“更多”菜单中，配置了备用域名的规则会出现“线路选择”。支持自动、固定主站或固定某个备用域名，显示当前使用线路和地址，并可在自动模式下重新检测。固定后不自动跳站。受保护规则继续隐藏域名，仅展示固定的线路编号：线路 1（主站）、线路 2……。

手动设置按规则和主备域名配置保存，不写回规则 JSON。修改主备域名后不沿用旧固定选择。

## 认证规则的默认策略

配置了 `auth`（包括兼容的旧登录 URL）的规则默认使用主站，不探测或自动切换备用线路。用户仍可在“线路选择”中手动固定线路；认证凭据必须满足该目标的 origins/pathPrefix 限制，Cookie 不会跨域复制。未配置 auth 的规则保持自动择优。

仅当作者已确认镜像共享认证体系时，才配置 `auth.allowHostSwitch: true`，并在 `auth.inject[].origins` 或 WebView 登录入口的 `origins` 中明确声明允许的备用来源。两项缺一不可。`allowHostSwitch` 是可选布尔值，默认 false，不会扩大 origins 的信任范围；自动认证请求仍受 pathPrefix 限制。修改 auth 后旧线路缓存和手动选择失效，重新应用默认策略。原生登录请求仍使用 auth 明确配置的登录地址。
